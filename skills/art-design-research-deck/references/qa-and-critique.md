# QA 与设计 critique

## 两条验收线

技术可打开与编辑质量必须分别检查。自动程序只能提供风险线索；空白面积、图形数量、布局多样性分数或 style fidelity 百分比不能证明设计成立。

实际交付 PPTX → 全页渲染 → contact sheet → 逐页放大检查。记录渲染器、字体/替代字体和版本；明确是否在目标 PowerPoint/Keynote 环境验证。HTML 或源代码没报错不等于 PPTX 没问题。

## 技术与证据检查

- overflow / overlap / clipping：检查真实字形、边界、图注、页脚、分组/旋转对象和图片遮挡；有意叠放要有理由。
- font substitution：中西文/韩文/数字覆盖、缺字、fallback、换行变化和字重是否正确。
- image resolution / aspect ratio：有效分辨率、像素化、拉伸、spread 顺序、裁切和细节对应。
- source traceability：每项作品、案例、引文、数字和重绘图都能通过 ID 找到具体出处；没有未解释的孤立引用或未绑定证据。
- speaker notes provenance：确认备注随文件保存，页面、证据和论点 ID 对应，完整来源可访问；不支持备注时核查随稿来源表或附录。
- caption consistency：语法、作品名/年份/credit、位置关系与编号一致，不能串图。
- typography hierarchy：论点、分析、作品标题、caption、source、footnote、folio 职能可辨，实际展示尺寸可读。
- native editability：文本、基本 shape、图片对象能独立选中修改；抽查每种元素类型和最复杂页；栅格化例外明确。
- 输出完整性：页数与 storyboard 一致，内容未被截短/静默丢弃，素材已嵌入，预览页数匹配，无未披露占位。

几何检测需区分 intentional overlap 与错误。矩形相交不等于可见冲突；文本框未出界也可能字形溢出。必须看渲染。来源/事实错误、丢字、核心作品被误裁、不可读与虚假可编辑性属于交付阻断项。

## 全 deck 设计 critique

用 contact sheet 和连续播放一起问：
- 是否连续多页相同构图？重复是否真的支持比较/阅读顺序？
- 是否所有图片尺寸过度一致、观看距离没有变化？
- 是否页密度和节奏过于平均？章节是否只有标题变化？
- 是否有无概念理由的 graphic gesture、gradient、装饰线或 blob？
- 是否出现 generic AI-presentation aesthetics，例如随处卡片、三图标三要点、统一大数字？
- 是否过度依赖 icon、shape 或 template motif？
- 是否该安静的页被填满？是否密集案例被过度留白而无法看见关系？
- 是否为了统一风格抹平案例差异、改变作品色彩或任意裁图？
- 是否图注与来源像事后塞入，破坏阅读？
- 把研究对象名称换掉后，这份 deck 是否几乎仍能原样使用？若能，重新检视视觉推导依据。
- 最终像套模板，还是读者能沿证据看出它从研究中形成？
- 重要决定的 Observed / Functional / Interpretive / User-defined 理由是否诚实？是否把功能性安排硬说成作品特征，或把编辑转译冒充作者意图？

这些问题是判断工具，不是每种构图必须出现一次的指标。刻意稳定的序列可成立；要解释稳定的阅读作用。

## 问题记录与修订

记录 page/element ID → 观察到的问题 → 影响 → 严重程度 → 拟议修复 → 复核结果。
技术问题优先修复源文件；证据不足回到研究；节奏失衡回到页序。删除无用装饰往往比补装饰有效，但不得把所有页都改为极简。

改后重渲染受影响页，核查相邻页与全 deck 缩略图；涉及全局字体、画布或模板参数时重渲染全稿。持续修复已知阻断问题，不以“只修一轮”提前结束。若环境限制无法验证，列明未验证项，不报全部通过。

交付说明包含：验证范围、来源台账、编辑性例外、已知限制、重大修订。未发生的真实 testcase 不可写为通过。

# 研究型 deck 工作流

## 双入口

**Reference-led mode**：收到 PPTX、PDF、网站、书籍、海报、moodboard 或图片，先做参考的 Design DNA 测量与观察，保留页号、元素和来源。此时是候选观察集，不是立即排版。随后核对研究目的与证据，再把参考的关系转译为 presentation system。无法访问的参考标记未读，不靠 URL 名字猜风格；多参考出现冲突时保留差异，不机械平均。

**Subject-led mode**：只有研究对象时，先调查其作品、出版物、网站、字体、材料、构图、信息密度和书籍结构，建立真实证据板；从不同案例共同点与反例推导系统。没有 reference deck 不意味着选择“艺术风模板”。

brief 记录对象、研究问题、受众、语言、页数、展示环境、输出格式、现有证据和用户限制。复用已知信息，只询问会改变结果的缺口。用户要求阶段审阅时遵守其停点；不自行添加每步必批的流程。

## 阶段契约

按任务规模选择记录量：快速课堂小稿使用 image → source → claim 对照和简短方向说明；30 页正式研究稿保留 claim ledger、evidence register、重要设计理由与 bibliography，可合并为少量文件。两者都核对事实、保留出处并检查实际交付，不把轻量理解为允许无来源。

主线不是一次性瀑布流程。让 Narrative ↔ Design DNA 互相修正；Slide Rhythm 或局部试排暴露缺图、弱论证或新的问题时返回 Research / Visual Evidence。先有足够证据才开始有目的的视觉实验，不要求研究全部结束。Critique 后修改源文件、重新导出并渲染，再复核；用户只要求小改时限定在相关环节。

| 阶段 | 输入 | 判断标准 | 输出 |
|---|---|---|---|
| Research | brief、用户资料、研究对象、可访问来源 | 作者/项目/时间可核对；事实、引文、分析分开；不足处不补造 | 研究问题、claim/source 台账、未知项与研究边界 |
| Visual Evidence | 研究问题与可获得原始图像 | 每张图能支持哪项观察；有完整图/细节/页序信息；清晰度与来源够用 | evidence register、真实证据板、缺图清单 |
| Narrative | 已验证 claims 与证据 | 推理有递进，案例不是陈列；每段能回答问题；允许跨案例比较 | 章节论证、逐页目的、证据绑定及参考文献预算 |
| Design DNA | narrative、reference 观察或 subject corpus、展示与用户要求 | 按四类理由区分观察、功能、转译与用户决定；不编造先例 | visual-direction memo、tokens、适用范围和例外 |
| Slide Rhythm | 逐页目的、证据实际尺寸、Design DNA | 连续观看有密度与尺度变化；停顿和重复有原因；caption 可容纳 | 有序 rhythm map 与低保真 storyboard |
| Build | storyboard、真实素材、tokens、内容 | 不吞字不拉伸图；内容/来源/坐标分开；先验证代表性难页 | 可复现源文件与元素清单、局部预览 |
| Native PPTX | build 源文件和原生生成器 | 文字/基本形状/图像可独立操作，页数与证据对应，非全页 flatten | PPTX、编辑性清单、任何栅格化例外 |
| Render | 实际 PPTX、可用字体与渲染器 | 从交付文件逐页渲染，页数一致，输出非空，记录字体替换 | 全部页面预览、contact sheet、渲染环境记录 |
| Critique | 渲染、storyboard、台账与编辑性检查 | 同时检查技术、证据、字体和全 deck 编辑质量 | 定位到页/元素的问题、严重程度、修订动作 |
| Revision | critique 和用户反馈 | 修复原因而非填装饰；改动后重渲染并核查邻页节奏；无未披露阻断项 | 修订 PPTX、预览、来源表与简短变更记录 |

以上输出可合并在少量项目文件里，不必每个名词生成独立文档。研究范围、页数和参考文献是否计入总数需在 brief 中明确。缺证据时回到 Research/Visual Evidence，不创建伪作品 placeholder。

## 节奏表

每页记录：page ID、章节、问题/论点、evidence ID、构图关系、图像尺度、文本密度、阅读时间、与前后页关系、caption/source 区域。密度结合图像复杂度、文字负担和观看任务判断，不只数字符。

dense → quiet → full-bleed → analytical → pause → comparison → conclusion 只是可用关系示例，不是循环模板。Full-bleed 仅在比例和作品完整性允许时使用。连排 spread 可保持稳定尺度以比较，随后改变观看距离进入 detail。

## 示例：30 页出版设计研究的应用

Sulki & Min，30 页书籍装帧／出版设计研究；简体中文；主线
Concept → Information → System → Material → Reading。仅当用户给出此研究框架时采用；不是其他项目的固定结构，也不是对其作品的事实结论。

- Concept：解释具体项目的问题与概念，有作者陈述时定位来源；自己的解释明确标注。
- Information：用真实内页、目录、文字层次或索引讨论信息组织。
- System：通过多页/多个实例检验规则、重复和例外。
- Material：需要书脊、装订、纸张、印刷或实物图；缺少出版参数时不得只凭照片断言纸种/工艺。
- Reading：用连续 spread、翻页关系或观看顺序讨论阅读体验，标记推断。

示例页数预算：导入与问题 3；Concept 4；Information 5；System 5；Material 5；Reading 4；综合比较与结论 2；来源索引 2，共 30。按用户要求与证据重分配，禁止每章强制等长。项目、palette/fonts 与工艺判断须来自实际研究。

首次实测先用同一组真实材料验证完整 spread、detail+全图、密集分析、安静转折、跨案例比较几种任务，再扩展到 30 页；它们是阅读任务而非预设样式。比较参考输入和仅主题输入是否都能产出有来源依据的系统。

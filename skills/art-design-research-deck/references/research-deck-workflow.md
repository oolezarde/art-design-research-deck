# 研究型 deck 工作流

## 双入口

进入制作或修订前，先登记已有的 PPTX、研究稿、图片、来源索引、claim/image/source ID、备注和已认可的页面。按 ID 继承；改页序时保存旧页→新页的映射，更新来源出现的位置。明确本轮的修改范围和保护项，保留可回退的版本。只改视觉时沿用现有研究和主张；过程中发现事实问题，单独指出并核实。

先确定交付物是现场演讲的辅助还是可独立阅读的研究稿；信息已经给出时直接沿用。为每一页指定角色：开场、背景、案例入口、证据、分析、综合比较、转场、结论或来源。独立阅读稿的分析页在画面上呈现主张、可见证据和"证据为何支持主张"的解释，备注只做补充；演讲辅助稿可以更精简，但结论与证据仍然连在一起。纯视觉入口、转场和暂停页按它们自己的角色处理，不需要统一加字。

**Reference-led mode**：收到 PPTX、PDF、网站、书籍、海报、moodboard 或图片时，先做参考的 Design DNA 测量与观察，保留页号、元素和来源。此时得到的是候选观察集，排版在核对研究目的与证据之后开始，把参考里的关系转译为 presentation system。无法访问的参考标记为未读；多份参考出现冲突时保留差异，让差异成为判断材料。

**Subject-led mode**：只有研究对象时，先调查其作品、出版物、网站、字体、材料、构图、信息密度和书籍结构，建立真实的证据板；从不同案例的共同点与反例推导系统。没有 reference deck 时，系统仍然从对象本身长出来，而不是从"艺术风"的模板里选。

brief 记录对象、研究问题、受众、语言、页数、展示环境、输出格式、现有证据和用户限制。复用已知信息，只询问会改变结果的缺口。用户要求阶段审阅时遵守其停点，其余环节按主线自行推进。

## 阶段契约

按任务规模选择记录量：快速课堂小稿用一张 image → source → claim 对照表和简短的方向说明；30 页正式研究稿保留 claim ledger、evidence register、重要设计理由与 bibliography，可以合并为少量文件。两种规模都核对事实、保留出处并检查实际交付，轻量指的是记录形式，不是来源要求。

主线不是一次性的瀑布流程。让 Narrative ↔ Design DNA 互相修正；Slide Rhythm 或局部试排暴露缺图、弱论证或新问题时，返回 Research / Visual Evidence。有了足够证据就可以开始有目的的视觉实验，不需要等研究全部结束。Critique 之后修改源文件、重新导出并渲染，再复核；用户只要求小改时限定在相关环节。

| 阶段 | 输入 | 判断标准 | 输出 |
|---|---|---|---|
| Research | brief、用户资料、研究对象、可访问来源 | 作者/项目/时间可核对；事实、引文、分析分开；不足处如实记为缺口 | 研究问题、claim/source 台账、未知项与研究边界 |
| Visual Evidence | 研究问题与可获得的原始图像 | 每张图能支持哪项观察；有完整图/细节/页序信息；清晰度与来源够用 | evidence register、真实证据板、缺图清单 |
| Narrative | 已验证的 claims 与证据 | 推理有递进，案例形成论证而不是陈列；每段能回答问题；允许跨案例比较 | 章节论证、逐页目的、证据绑定及参考文献预算 |
| Design DNA | narrative、reference 观察或 subject corpus、展示与用户要求 | 按四类理由区分观察、功能、转译与用户决定 | visual-direction memo、tokens、适用范围和例外 |
| Slide Rhythm | 逐页目的、证据实际尺寸、Design DNA | 连续观看有密度与尺度变化；停顿和重复有原因；caption 有位置 | 有序 rhythm map 与低保真 storyboard |
| Build | storyboard、真实素材、tokens、内容 | 文字完整、图片等比；内容/来源/坐标分开；先验证代表性难页 | 可复现源文件与元素清单、局部预览 |
| Native PPTX | build 源文件和原生生成器 | 文字/基本形状/图像可独立操作，页数与证据对应 | PPTX、编辑性清单、栅格化例外 |
| Render | 实际 PPTX、可用字体与渲染器 | 从交付文件逐页渲染，页数一致，输出非空，记录字体替换 | 全部页面预览、contact sheet、渲染环境记录 |
| Critique | 渲染、storyboard、台账与编辑性检查 | 同时检查技术、证据、字体和全 deck 编辑质量 | 定位到页/元素的问题、严重程度、修订动作 |
| Revision | critique 和用户反馈 | 修复原因而不是补装饰；改动后重渲染并核查邻页节奏；阻断项全部披露 | 修订 PPTX、预览、来源表与简短变更记录 |

进入全稿 Build 前，完成结构机制转译、有限色卡、字体角色与代表页检查，细节见 [视觉系统与版式](visual-system-layout.md)。每次修订保留已经奏效的比较、尺度和密度关系；核对内容、来源、备注与新视觉的一致，重建页面时研究资产随页面一起迁移。

以上输出可以合并在少量项目文件里。研究范围、页数和参考文献是否计入总数在 brief 中明确。缺证据时回到 Research / Visual Evidence 补齐，草稿阶段用明确的缺证据注记占位，而不是伪作品 placeholder。

## 节奏表

每页记录：page ID、章节、问题/论点、evidence ID、构图关系、图像尺度、文本密度、阅读时间、与前后页的关系、caption/source 区域。密度结合图像复杂度、文字负担和观看任务判断。

dense → quiet → full-bleed → analytical → pause → comparison → conclusion 是可用关系的示例，具体顺序由论证决定。Full-bleed 在比例和作品完整性允许时使用。连排 spread 可以保持稳定尺度以便比较，随后改变观看距离进入 detail。

## 示例：30 页出版设计研究的应用

Sulki & Min，30 页书籍装帧／出版设计研究；简体中文；主线 Concept → Information → System → Material → Reading。这个框架来自该项目的用户要求，供理解流程用；其他项目按自己的研究问题建立结构。

- Concept：解释具体项目的问题与概念，有作者陈述时定位来源；自己的解释明确标注。
- Information：用真实内页、目录、文字层次或索引讨论信息组织。
- System：通过多页/多个实例检验规则、重复和例外。
- Material：需要书脊、装订、纸张、印刷或实物图；缺少出版参数时，纸种和工艺的判断标为推测。
- Reading：用连续 spread、翻页关系或观看顺序讨论阅读体验，标记推断。

示例页数预算：导入与问题 3；Concept 4；Information 5；System 5；Material 5；Reading 4；综合比较与结论 2；来源索引 2，共 30。按用户要求与证据重新分配，各章长度随论证需要变化。项目、palette/fonts 与工艺判断来自实际研究。

首次实测先用同一组真实材料验证完整 spread、detail+全图、密集分析、安静转折、跨案例比较几种阅读任务，再扩展到 30 页。比较参考输入和仅主题输入是否都能产出有来源依据的系统。

案例修订曾以分析页约 50–100 字、约 25–35% 的备注分析上屏作为尺度；这是那个项目的记录，其他项目按页面角色和论证充分性判断。最多两种底色、特定字族和删除左下页脚同样是项目偏好，供参考，不是通用规则。

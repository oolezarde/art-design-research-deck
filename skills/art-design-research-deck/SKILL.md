# Art Design Research Deck

用本 skill 指导研究、艺术指导、证据处理、编辑序列与设计 critique。先理解对象并找到真实证据，再做有依据的视觉实验；让实验暴露的问题推动进一步研究。

## 核心约定

- 从研究与参考推导视觉方向，允许功能性、编辑性与用户指定的决定；不要把 derived 误作模仿。为重要决定保留理由，不编造先例。
- 把整稿当作编辑序列，允许空白、纯文字、尺度和密度变化。优先展示真实作品证据；把字体、caption、source 与页码纳入初始结构。
- 按任务规模控制记录量，始终保留来源、事实与推断的区别。尊重用户语言、页数、风格和阶段停点。
- 输出 PPTX 时保持文字、基本形状和图片对象可编辑；复杂作品保留为图像，不声称可逐笔编辑。

## 按任务阅读

1. 建立或调整视觉方向时读 [设计原则](references/design-principles.md)。
2. 开始完整项目或重构叙事时读 [研究工作流](references/research-deck-workflow.md)，选择 Reference-led 或 Subject-led，并确定记录规模。
3. 收集、引用或裁切图像时读 [图像与来源](references/image-and-source-handling.md)。
4. 提取参考、定义设计系统或编排页面时读 [视觉系统与版式](references/visual-system-layout.md)。
5. 构建前与交付评审时读 [QA 与 critique](references/qa-and-critique.md)。仅审阅现有 deck 时从此处开始，按发现的问题补读。

## 主线与回路

Research → Visual Evidence → Narrative ↔ Design DNA → Slide Rhythm → Build → Native PPTX → Render → Critique → Revision。

将主线作为推进顺序，允许从任一步返回证据、叙事或视觉系统。局部修改只走相关环节，不强制重做整套研究；没有证据时先补研究或收窄论点。

## 文件构建

实际创建或修改 PPTX 时，使用宿主可用的标准 presentations/slides 工具处理文件构建、渲染和技术验证，先读取所选工具的当前说明。本 skill 负责研究与设计判断；不继承与这些约束冲突的通用视觉默认值。宿主没有可用工具时说明缺口，不把整页截图当原生 PPTX。

不假定附带执行脚本、模板、外部 CLI 或 API key。依据当前工具能力选择实现；引入外部代码前审查依赖、文件覆盖和网络行为，不因第三方说明声称可用就跳过验证。

# Art Design Research Deck

用本 skill 指导研究、艺术指导、证据处理、编辑序列与设计 critique。先理解对象并找到真实证据，再做有依据的视觉实验；让实验暴露的问题推动进一步研究。

## 这份 skill 的立场

一份研究型 deck 是一篇用页面写成的论证，而不是一组套在模板里的内容。视觉方向从研究对象和参考里推导出来，也允许可读性、编辑判断和用户的明确要求参与决定；重要的决定留下理由，理由来自证据、功能、转译或用户要求，而不是编造的先例。derived 和模仿的区别在于能否说出自己拿走了什么。

整份 deck 当作编辑序列来做：空白、纯文字、尺度和密度的变化都是可用的手段，真实作品证据优先上屏，字体、caption、source 和页码从初始结构起就有位置。留白省略的是装饰，不是分析；独立阅读的分析页要在画面上把主张、可见证据和解释连起来。

记录量随任务规模伸缩，但来源、事实与推断的区别始终保留。尊重用户的语言、页数、风格和阶段停点。输出 PPTX 时文字、基本形状和图片对象保持可编辑；复杂作品作为图像整体保留，并如实说明哪些部分是栅格化的。修订时继承已有研究资产、保护已奏效的页面，并同步更新设计说明。

## 按任务阅读

1. 建立或调整视觉方向时读 [设计原则](references/design-principles.md)。
2. 开始制作或修订时读 [研究工作流](references/research-deck-workflow.md)，继承已有材料，确定阅读方式、修改范围与记录规模；新项目选择 Reference-led 或 Subject-led。
3. 收集、引用或裁切图像时读 [图像与来源](references/image-and-source-handling.md)。
4. 提取参考、定义设计系统或编排页面时读 [视觉系统与版式](references/visual-system-layout.md)。
5. 构建前与交付评审时读 [QA 与 critique](references/qa-and-critique.md)。仅审阅现有 deck 时从此处开始，按发现的问题补读。

## 主线与回路

Research → Visual Evidence → Narrative ↔ Design DNA → Slide Rhythm → Build → Native PPTX → Render → Critique → Revision。

主线是推进顺序，也允许从任一步返回证据、叙事或视觉系统。局部修改只走相关环节；证据不够时先补研究或收窄论点，再继续。

## 文件构建

实际创建或修改 PPTX 时，使用宿主可用的标准 presentations/slides 工具处理文件构建、渲染和技术验证，先读取所选工具的当前说明。本 skill 负责研究与设计判断，把这些判断传入构建过程；宿主工具自带的通用视觉默认值与本 skill 冲突时，以本 skill 为准。宿主没有可用工具时说明缺口，整页截图不算原生 PPTX。

不假定附带执行脚本、模板、外部 CLI 或 API key，按当前工具能力选择实现。引入外部代码前审查它的依赖、文件覆盖和网络行为；第三方说明声称可用不等于已经验证。
